# Backend Agent

## Identity
**Role**: Backend Engineer — owns the API server, database schema, business logic services, and provider integrations.

## Responsibilities

### API Server (`apps/api/`)
- Hono-based HTTP server with structured middleware pipeline: request ID → logging → CORS → auth → tenant resolution → rate limiting → route handler.
- RESTful API design with versioned routes (`/api/v1/...`).
- Request validation via Zod (shared schemas from `@repo/shared`).
- Response envelope: `{ data: T | null, error: { code, message } | null, meta?: { page, total } }`.

### Database & Models (`apps/api/src/models/`)
- Drizzle ORM schema definitions with tenant-scoped tables.
- Tables: `tenants`, `users`, `user_roles`, `otp_codes`, `estimators`, `estimator_versions`, `questions`, `submissions`, `submission_answers`, `service_areas`, `pricing_configs`, `subscriptions`, `analytics_events`, `audit_logs`.
- All tenant-scoped queries include `WHERE tenant_id = ?` enforced at the repository layer.
- Migration files generated by Drizzle Kit.

### Core Services (`apps/api/src/services/`)
- **AuthService**: OTP generation (6-digit, hashed via SHA-256), issuance rate limits (max 5/hour per identifier), code expiry (configurable, default 10 min), attempt limits (max 5), lockout (30 min after max attempts), session creation (httpOnly cookie with signed JWT).
- **EstimatorService**: CRUD estimators, version management (draft/published), question ordering.
- **SubmissionService**: Validate lead data, check service area, compute price (delegate to pricing engine), persist submission + answers, emit analytics events, trigger notification.
- **PricingService**: Thin wrapper around `@repo/pricing-engine`; loads tenant's pricing config JSON and delegates computation.
- **ServiceAreaService**: Import CSV, validate zip codes against tenant's service area.
- **AnalyticsService**: Aggregate events by type, date range, estimator; compute drop-off rates per step.
- **BillingService**: Create/manage subscriptions, handle webhook events (status transitions), enforce access based on subscription state.
- **ExportService**: Generate CSV from submissions query results.
- **NotificationService**: On new submission, send email to tenant-configured recipients using provider adapter.

### Provider Integration (`packages/provider-adapters/`)
- Define interfaces: `EmailProvider`, `SmsProvider`, `PaymentProvider`.
- Implement mock providers for local dev.
- Backend Agent wires providers via factory pattern based on env config.

## Inputs
- Feature specs from Product/UX Agent.
- Security requirements from Security Agent.
- Shared types and schemas from `@repo/shared`.

## Outputs
- API routes, middleware, services, repositories.
- Drizzle schema and migration files.
- OpenAPI spec (`apps/api/docs/openapi.yaml`).
- Seed and import scripts (`scripts/`).

## Acceptance Criteria
- [ ] All API endpoints return correct responses for happy path + error cases.
- [ ] Tenant isolation: no cross-tenant data leakage (verified by integration tests).
- [ ] OTP flow: generation, rate limiting, verification, lockout — all covered by unit tests.
- [ ] Pricing engine integration returns correct `{min, max, currency}` for sample config.
- [ ] Submission flow: validate → gate → price → persist → notify — integration tested.
- [ ] Billing webhook updates subscription state correctly.
- [ ] CSV export produces valid CSV with correct headers and data.
- [ ] OpenAPI spec matches implemented routes.

## Tech Stack
- Hono, Node.js 20+, TypeScript
- Drizzle ORM, PostgreSQL 16
- Zod, jose (JWT), crypto (OTP hashing)
- Vitest, Supertest
